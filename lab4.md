## 2. Описание алгоритма и теоретические оценки

### 2.1. Постановка задачи

Дан упорядоченный по возрастанию массив $A$ из $n$ элементов и ключ $q$. Требуется найти индекс $i$, для которого $A[i] = q$, либо установить, что такого элемента нет (вернуть $-1$). Поиск называется **успешным**, если ключ присутствует в массиве, и **неуспешным** в противном случае.

### 2.2. Идея двоичного поиска

Алгоритм применим только к **упорядоченному** массиву. На каждом шаге рассматривается средний элемент текущего отрезка $[lo, hi]$. Результат сравнения $A[mid]$ с ключом $q$ позволяет отбросить ровно половину отрезка:

- если $A[mid] = q$ — элемент найден;
- если $A[mid] < q$ — искомое значение находится правее, $lo := mid + 1$;
- если $A[mid] > q$ — искомое значение находится левее, $hi := mid - 1$.

Поскольку после каждого сравнения длина рассматриваемого отрезка уменьшается вдвое, число сравнений в худшем случае

$$C_{\max} = \lfloor \log_2 n \rfloor + 1 = \Theta(\log n).$$

Среднее число сравнений при успешном поиске с равновероятным расположением ключа также имеет порядок $\Theta(\log n)$ и близко к $\log_2 n$.

### 2.3. Сводная оценка сложности

| Алгоритм | Упорядоченность | Лучший | Средний | Худший | Доп. память |
|---|---|---|---|---|---|
| Двоичный | Требуется | $\Theta(1)$ | $\Theta(\log n)$ | $\Theta(\log n)$ | $O(1)$ |

### 2.4. Типичные ошибки реализации

- переполнение при вычислении середины как $(lo + hi)/2$ — в Python несущественно, но используется безопасная форма $lo + (hi - lo)/2$;
- неверные границы цикла (`<` вместо `<=`), приводящие к пропуску элемента;
- применение к неотсортированному массиву — даёт неверный результат без сообщения об ошибке.

## 3. Блок-схема алгоритма

```mermaid
flowchart TD
    A([Начало]) --> B[/Ввод A, n, q/]
    B --> C["lo := 0; hi := n − 1; cmps := 0"]
    C --> D{lo ≤ hi?}
    D -- Нет --> E[/Вернуть (−1, cmps)/] --> Z([Конец])
    D -- Да --> F["mid := lo + (hi − lo) // 2; cmps := cmps + 1"]
    F --> G{"A[mid] = q?"}
    G -- Да --> H[/Вернуть (mid, cmps)/] --> Z
    G -- Нет --> I{"A[mid] < q?"}
    I -- Да --> J["lo := mid + 1"] --> D
    I -- Нет --> K["hi := mid − 1"] --> D
```

## 4. Листинг программы

import random
import time
import math
import matplotlib.pyplot as plt

def binary_search(a, q):
    lo, hi = 0, len(a) - 1
    cmps = 0
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        cmps += 1
        if a[mid] == q:
            return mid, cmps
        elif a[mid] < q:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1, cmps

def make_uniform_data(n, seed=42):
    rng = random.Random(seed)
    data = rng.sample(range(10 * n), n)
    data.sort()
    return data

def benchmark(func, data, queries):
    start = time.perf_counter()
    all_cmps = []
    for q in queries:
        _, c = func(data, q)
        all_cmps.append(c)
    elapsed = time.perf_counter() - start
    avg_time = elapsed / len(queries)
    return avg_time, all_cmps

if __name__ == "__main__":
    SIZES = [5_000, 50_000, 500_000]
    K = 2000

    rng = random.Random(7)

    times = []
    avg_cmps = []
    all_cmps_per_n = []

    for n in SIZES:
        print(f"\n=== n = {n} ===")
        data = make_uniform_data(n)

        queries = [rng.choice(data) for _ in range(K)]

        t, cmps_list = benchmark(binary_search, data, queries)
        avg_c = sum(cmps_list) / len(cmps_list)

        times.append(t)
        avg_cmps.append(avg_c)
        all_cmps_per_n.append(cmps_list)

        theory = math.log2(n)
        print(f"  Среднее время:      {t*1e6:>8.2f} мкс/запрос")
        print(f"  Среднее сравнений:  {avg_c:>8.2f}")
        print(f"  Теория log2(n):     {theory:>8.2f}")

    plt.figure(figsize=(8, 5))
    plt.plot(SIZES, [t * 1e6 for t in times], marker="o",
             color="tab:blue", label="Двоичный поиск")
    plt.xscale("log")
    plt.xlabel("n (лог. шкала)")
    plt.ylabel("Среднее время запроса, мкс")
    plt.title("Вариант 7: время запроса (двоичный поиск)")
    plt.legend()
    plt.grid(True, which="both", ls="--", alpha=0.4)
    plt.tight_layout()
    plt.savefig("var7_binary_time.png", dpi=150)
    plt.close()

    plt.figure(figsize=(8, 5))
    plt.plot(SIZES, avg_cmps, marker="s",
             color="tab:blue", label="Факт. среднее")
    plt.plot(SIZES, [math.log2(n) for n in SIZES], marker="^",
             color="tab:green", linestyle="--", label="Теория log2(n)")
    plt.xscale("log")
    plt.xlabel("n (лог. шкала)")
    plt.ylabel("Среднее число сравнений")
    plt.title("Вариант 7: сравнения (двоичный поиск)")
    plt.legend()
    plt.grid(True, which="both", ls="--", alpha=0.4)
    plt.tight_layout()
    plt.savefig("var7_binary_cmps.png", dpi=150)
    plt.close()

    n_big_idx = len(SIZES) - 1
    n_big = SIZES[n_big_idx]
    cmps = all_cmps_per_n[n_big_idx]
    emp_mean = sum(cmps) / len(cmps)
    theory = math.log2(n_big)

    plt.figure(figsize=(8, 5))
    plt.hist(cmps, bins=15, edgecolor="black", alpha=0.7, color="tab:blue")
    plt.axvline(emp_mean, color="red", ls="--", linewidth=2,
                label=f"Факт. среднее = {emp_mean:.2f}")
    plt.axvline(theory, color="green", ls=":", linewidth=2,
                label=f"Теория log2(n) ≈ {theory:.2f}")
    plt.xlabel("Число сравнений на запрос")
    plt.ylabel("Частота")
    plt.title(f"Б7: гистограмма сравнений — двоичный поиск, n = {n_big}")
    plt.legend()
    plt.grid(True, alpha=0.3)
    plt.tight_layout()
    plt.savefig("var7_binary_hist.png", dpi=150)
    plt.close()

    print("\nГотово. Сохранены файлы:")
    print("  var7_binary_time.png   — график времени")
    print("  var7_binary_cmps.png   — график сравнений vs теория")
    print("  var7_binary_hist.png   — гистограмма (Б7)")

## 9. Контрольные вопросы (краткие ответы)

1. **Задача поиска** — найти индекс элемента $A[i]=q$ или установить его отсутствие. Неуспешный поиск дороже: у последовательного всегда $n$ сравнений, у двоичного — $\lfloor\log_2 n\rfloor+1$.
2. **Формула среднего числа сравнений последовательного поиска:** $C_{\text{ср}}=\frac{1+2+\ldots+n}{n}=\frac{n+1}{2}$, так как ключ равновероятно находится на любой позиции.
3. **Барьерный элемент** записывается в конец массива и гарантирует выход из цикла без проверки границы — константа сокращается примерно вдвое, асимптотика остаётся $\Theta(n)$.
4. **Двоичный поиск требует упорядоченности**, потому что решение «идти влево или вправо» опирается на инвариант: все элементы левее $mid$ меньше $A[mid]$, все правее — больше. В неотсортированном массиве инвариант нарушается, результат неверен.
5. **При $n=10^6$** двоичный поиск в худшем случае выполнит $\lfloor\log_2 10^6\rfloor+1 = 20$ сравнений.
6. **Пробная позиция в интерполяционном поиске:** $mid = lo + \left\lfloor\frac{(q-A[lo])(hi-lo)}{A[hi]-A[lo]}\right\rfloor$, основана на предположении о **равномерном** (линейном) распределении ключей по индексам.
7. **Деградация интерполяционного поиска** до $\Theta(n)$ происходит при **неравномерном распределении**, например степенном $\lfloor 10^6 u^3\rfloor$: почти все значения сосредоточены у нуля, формула угадывает позицию плохо.
8. **Условие окупаемости сортировки:** $k > \dfrac{c_2\,n\log_2 n}{c_1 n - c_3\log_2 n}\approx\dfrac{c_2}{c_1}\log_2 n$. Порог растёт логарифмически, потому что сортировка стоит $n\log n$, а каждый запрос экономит $\sim n$ — при делении $n$ сокращается.
9. **Индексы ускоряют выборку** (поиск по B-дереву за $\log n$), но **замедляют вставку** (требуется перестроение индекса). Классический компромисс между скоростью чтения и записи.
10. **Все вхождения ключа за $O(\log n+m)$:** двумя двоичными поисками находятся левая граница (первое вхождение $\ge q$) и правая (первое вхождение $> q$); затем выводится срез длиной $m$.
